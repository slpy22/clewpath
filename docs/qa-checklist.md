# QA 체크리스트 - 실사용으로 확인해야 할 것들

자동 테스트로 못 덮는(실제 기기·실제 세션이 필요한) 검증 항목.
확인되면 체크하고 날짜를 남긴다. 릴리스 전 미확인 항목은 릴리스 노트에 명시.

## P1 - 훅 기반 세션 상태 감지 (0.3.16 예정)

- [ ] 새 `claude` 세션 시작 시 SessionStart 이벤트가 Host 에 도착하는가
      (훅은 세션 시작 시 로드되므로, settings.json 등록 이후 **새로 시작한** 세션부터)
- [ ] 질문 제출 -> thinking, 턴 종료 -> ready 가 실제 대화 흐름대로 바뀌는가
- [ ] 권한 프롬프트 발생 시 Notification 이 `permission` 으로 분류되는가
      (문구 기반 분류 - Claude 버전/로케일에 따라 문구가 바뀌면 `waiting` 으로
      떨어진다. 바뀐 문구 발견 시 hooks._classify_notification 에 추가)
- [ ] 세션 여러 개 동시 실행 시 session_id 별로 상태가 섞이지 않는가
- [ ] 훅 등록 후 Claude Code 사용감에 부작용이 없는가
      (훅 실패 시 경고가 세션에 뜨지 않는지 - cmd 가 exit /b 0 이라 없어야 정상)
- [ ] Host 가 꺼져 있을 때 claude 세션이 느려지지 않는가 (curl -m 3 상한)
- [ ] 포트 폴백(5100 점유 -> 5101) 시 clewpath-hook.cmd 가 새 포트로 재작성되는가
- [ ] 외부 사용자 PC(회사 PC 포함)에 curl.exe 가 있는가 (Win10 1803+ 기본.
      LTSC/구형에서 없으면 훅이 조용히 무동작 - 감지 로직 필요할 수 있음)
- [ ] 릴레이 경유 원격 목록에도 runtime 필드가 나오는가 (connector 프록시 경유)
- [ ] 다른 도구가 등록한 훅과 공존하는가 (비파괴 병합 - 자동테스트 있음, 실물 재확인)
- [ ] Claude Code 업데이트 후 훅 페이로드(hook_event_name/session_id)가 유지되는가

## P2 - 웹푸시 (구현 중)

- [ ] Android Chrome: 알림 수신 + 알림 탭 -> 해당 세션 열림
- [ ] Android: 브라우저 완전 종료 상태에서도 푸시 수신
- [ ] iOS(16.4+): 홈 화면 추가한 PWA 에서 구독/수신 (Safari 탭에선 불가가 정상)
- [ ] 같은 권한요청이 60초 내 중복 알림되지 않는가 (dedupe)
- [ ] 구독한 기기를 여러 대 두면 전부 수신하는가
- [ ] 만료/해지된 구독(410 Gone)이 자동 정리되는가
- [ ] 릴레이 화면(clewpath.pyongso.com)에서 구독 -> Host 재기동 후에도 발송되는가
      (구독 영속 확인)
- [ ] 알림 내용에 코드/경로가 과하게 노출되지 않는가 (본문 정책 확인)
