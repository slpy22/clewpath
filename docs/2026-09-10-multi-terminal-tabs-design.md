## 1. 문제

현재 ClewPath 뷰어는 **한 번에 한 세션의 터미널만** 열어둘 수 있다. 다른 세션의
터미널을 열면 보고 있던 터미널이 닫힌다. 여러 프로젝트/세션을 오가며 실제로
**작업**(양방향 터미널 입력)하려면 매번 목록으로 나갔다가 다시 들어와야 해서
흐름이 끊긴다.

사장님이 원하는 것: **브라우저 탭처럼 여러 세션 터미널을 동시에 열어두고,
클릭 한 번으로 전환하며 작업.** 떠나 있던 탭의 터미널은 백그라운드에서 살아있어야
한다(작업 상태·프로세스 유지).

### 모니터링(v0.6.x)과 다른 축

| | 멀티세션 모니터링 (v0.6.x) | 이번 기능 (v0.7.0) |
|---|---|---|
| 성격 | **관전** (읽기전용 tail) | **작업** (양방향 웹터미널) |
| 대상 | 에이전트↔에이전트 감독 | 내가 여러 세션에 직접 입력 |
| 동시성 | N개 타임라인 병합 관전 | N개 터미널 열어두고 **전환** |

즉 모니터링은 "위에서 내려다보는 감독석", 이번 건 "여러 작업대를 오가는 작업자".
둘은 겹치지 않고 **상호 보완**한다(§4 에서 모니터 스트림을 재사용).

## 2. 기술 전제 (코드 실측으로 확정, 2026-09-10)

핵심 결론부터: **"1개 제한"은 순전히 PWA UI 제약이다. 서버·릴레이는 이미 멀티
터미널을 지원한다.** 아래는 실제 코드 근거.

- **서버는 세션별 PTY 를 dict 로 여러 개 관리한다.** `webterm._ACTIVE:
  dict[str, _TermSession]` (키 = `fork_id or session_id`, 전역 개수 상한 없음,
  webterm.py:60·397·459). 세션당 PTY 1개이고, 화면(WS)이 닫혀도 **PTY 는
  유지(persist)** 되며 재접속 시 버퍼 tail 을 되감아준다(webterm.py:9·409-416).
  → 여러 세션의 터미널을 동시에 살려두는 것은 서버가 이미 하는 일.
- **유일한 서버측 제약은 "한 세션 = 화면 1개"** 뿐(새 화면이 붙으면 이전 화면을
  밀어냄, webterm.py:11·407-408). *다른* 세션 터미널을 막지 않는다.
- **릴레이는 rid(요청ID)로 다중 스트림을 지원한다.** `connector.self.streams[rid]`
  (connector.py:439·485), 클라이언트도 `Conn.streams=Map()` 로 터미널은 `'t'+seq`,
  재개는 `'s'+`, 모니터는 `'mon'+` 네임스페이스(index.html:616·731·744·754).
  → 여러 터미널을 rid 를 여러 개 여는 방식으로 동시에 터널링 가능.
- **막고 있는 곳은 PWA 한 곳뿐**: 활성 터미널 핸들이 **전역 단수** `let _term=null`
  (index.html:1636), 새로 열 때마다 `_term.close()` 로 기존 것을 닫는다
  (index.html:1778·1836), 화면은 **단일 `#paneDetail`**(index.html:77-78), 진입 시
  `main.innerHTML=''` 후 **xterm 인스턴스 딱 1개**(index.html:1776·1813). 탭바 없음.
- **자원 비용(불변)**: 터미널 1개 = `claude` 프로세스 1개(webterm.py:445-459).
  N개 열면 claude 프로세스가 **N개** 뜬다(각각 Job Object 로 고아 방지).
  → 이건 UI 를 고쳐도 그대로다. 아래 §6 에서 소프트 상한으로 다룬다.

**최종 판정: "서버 재설계 없이 UI 레이어만 확장"하면 된다.** 모니터 기능이 이미
"1 room = N세션"을 구현·검증했으므로 릴레이 다중화도 검증된 길이다.

## 3. 확정된 설계 결정 (office-hours 3문)

| 결정 | 선택 | 대안(기각) |
|---|---|---|
| **사용 형태** | 탭 전환(독립 세션들) — 클릭 전환, 백그라운드 유지 | 분할화면 / 모니터뷰 승격 / 탭+분할 혼합 |
| **연결 모델** | **전경 1개만 라이브 WS**, 배경 탭은 PTY persist 로 상태 유지 | 모든 탭 동시 라이브 WS(N개) |
| **Phase 1 범위** | 탭바 + 세션별 PTY keep-alive + 전환 시 reattach + 워킹셋 복원 + 소프트 상한 | 배경 탭 라이브 배지까지 초판 / 탭별 스크롤백 보존까지 초판 |

### 왜 "전경만 라이브"인가 (핵심 설계)

브라우저 탭의 심성 모형과 정확히 일치하고, **모바일에 안전**하다:

- 백그라운드 탭의 claude 프로세스는 서버에서 **계속 살아있다**(persist PTY). 즉
  "탭을 열어둔다"는 약속은 지켜진다 — 떠나 있어도 작업은 진행/보존된다.
- 화면(WS)만 전경 탭 1개가 가진다. 전환하면 이전 탭 화면 WS 를 닫고 대상 탭에
  재접속 → **tail 버퍼 리플레이**로 최근 내용이 즉시 복원된다(webterm.py:409-416).
- 결과적으로 **동시 WS/전송 부하가 오늘과 동일**(라이브 터미널 1개). 모바일
  배터리·연결수 부담이 늘지 않는다. "N개 동시 라이브"는 Phase 2 의 배지 신호로
  더 싸게 대체한다(§4).

## 4. 백그라운드 탭 활동 표시 — 모니터 스트림 재사용 (Phase 2)

"떠나 있는 탭에서 새 출력이 났는지" 를 알려주려고 N개 라이브 터미널 WS 를 유지할
필요가 없다. **이미 있는 모니터 tail 스트림**(webmonitor: 1 WS 로 N세션 jsonl 을
오프셋 tail, 이벤트에 `session_id` 포함, webmonitor.py:31-104)을 재사용한다:

- 열려있는 탭들의 `session_id` 를 모니터 그룹으로 구독(1 WS) → 각 세션에 새
  이벤트가 append 되면 해당 **탭에 `●` 활동 배지**를 켠다.
- 전경 = 라이브 터미널 1개, 배경 활동 신호 = 모니터 스트림 1개. **총 WS 2개**로
  "N개 탭이 다 살아 움직이는" 경험을 만든다. 모바일에서도 가볍다.

이 재사용이 이번 기획의 가장 우아한 지점 — 작업(터미널)과 관전(모니터)을 한
화면에서 합치되 부하는 상수로 유지한다.

## 5. UI/UX 설계

### 5-1. 데스크톱

```
┌───────────────────────────────────────────────┐
│ ● 포털개발  │ ○ 논문서비스●│ ○ KoreaPedia │  + │  ← 탭바(세션색 점)
├───────────────────────────────────────────────┤
│                                                 │
│   (전경 탭의 라이브 xterm 터미널)                │
│                                                 │
└───────────────────────────────────────────────┘
```
- 탭 = 세션색 점(모니터와 동일 팔레트 재사용) + 세션명 + `×`(닫기). 우측 `+` 로
  세션 추가(기존 세션 피커 재사용).
- 배경 탭에 `●` = 새 활동(Phase 2). 전경 탭은 배지 자동 소거.
- 활성 탭 강조(밑줄/배경). 오버플로 시 가로 스크롤.

### 5-2. 모바일

- 탭바 = **가로 스크롤 칩 스트립**(상단). 칩은 세션색 점 + 짧은 이름.
- 탭이 많으면 칩 스트립 + 우측 `▾` 로 전체 목록 시트(bottom sheet).
- 기존 모바일 터미널 UX 그대로 승계: wakeLock(화면 꺼짐 방지, index.html:1854),
  관성 스크롤·핀치 폰트·보조키바(`attachMobileTermUX`, index.html:1661·1849),
  `document.hidden` 폴링 억제(index.html:959).
- 전경 1개만 라이브라 **모바일 이탈/복귀가 견고**: 앱 나갔다 오면 relay 재연결
  (지수 백오프, index.html:772-785) 후 전경 탭이 persist PTY 에 재접속·리플레이.
  배경 탭 프로세스는 서버에서 안 죽는다(client_offline 은 화면만 뗀다,
  connector.py:565-566).
- (Phase 2) 좌우 스와이프로 탭 전환.

### 5-3. 상태 보존

- 열린 탭 목록(세션 id 배열) + 활성 탭을 **localStorage** 에 저장(모니터 divider
  `sm_monvw` 선례처럼). 앱을 다시 열면 워킹셋 복원.
- 단, PTY 는 서버 persist 라 새로고침해도 재접속으로 이어짐.

## 6. 리스크 / 엣지케이스

- **자원(N배 프로세스)**: 탭 N개 = claude N개. 폭주 방지로 **소프트 상한 + 경고**
  (예: 6개 초과 시 확인). 모니터가 `_MAX_SESSIONS=8`(webmonitor.py:28)을 둔 선례.
  Phase 1 에 포함.
- **같은 세션 중복 탭 금지**: webterm 은 `session_id` 로 키잉하므로 같은 세션을 두
  탭에 열면 서로 화면을 밀어낸다(webterm.py:407-408). **UI 에서 세션 id 로
  dedupe**(이미 열린 탭이면 그 탭으로 포커스).
- **다른 기기와 화면 경합**: 같은 세션을 다른 기기에서도 보면 "화면 1개" 규칙으로
  한쪽이 밀린다. 정상 동작이므로 문구로 안내.
- **불가침 원칙 준수**: 탭 개설 = 평범한 `claude --resume`(webterm.py:312-337).
  jsonl·설정 무수정. 새 claude 파일 접근 없음 → CLAUDE.md 원칙에 저촉 없음.
  (모니터와 달리 이건 사용자 명시 입력을 받는 양방향이므로 오히려 재개와 동급.)
- **재개 충돌**: 하위 세션이 외부 프로세스에 점유 중이면(관리 에이전트가 `-p`
  실행 중) 그 세션 탭 열기는 기존과 동일하게 충돌 안내. 새 리스크 아님.
- **자동 재부착 부재**: 터미널 자체 하트비트/자동 재부착은 현재 없음(모니터에만
  있음, webmonitor.py:26·98). Phase 2 에서 전경 탭 자동 재부착 검토.

## 7. Phase 구분 (devflow 백로그 고정용)

## 9. plan-eng-review 교정 (2026-09-10) — §3·§7보다 우선

아키텍처 리뷰(외부 보이스 codex→Claude 서브에이전트 폴백, 코드 실측 교차검증)에서
초안 §2의 낙관("서버 변경 0, UI만")이 **틀렸음**이 드러났다. 근거와 교정:

### 9-1. 뒤집힌 전제 (코드 근거)
- **`close()`는 릴레이 모드에서 서버 화면을 안 뗀다.** 클라이언트
  `startTerminal().close()`는 `this.streams.delete(id)`만 한다(index.html:750).
  connector 는 로컬 webterm WS 의 EOF 나 device-wide `client_offline` 에서만 rid 를
  정리한다(connector.py:380·566). **rid 단위 stop 프레임이 프로토콜에 없다** →
  "배경 탭 WS만 뗀다"는 기능은 **신규 프로토콜(connector+relay)** 이 필요.
  (로컬 iframe 모드는 실제 WS close 라 문제 없음 — 릴레이 모드 한정.)
- **보유 xterm은 서버의 '항상 리플레이'와 충돌.** 재접속 시 서버가 무조건
  tail(~60k)+배너를 리플레이한다(webterm.py:409). 스크롤백을 이미 쥔 보유 xterm 은
  **이중 렌더** → "리플레이 억제" 서버 플래그 없이는 성립 안 함.
- **릴레이 재연결·모바일 백그라운드 복귀 시 터미널이 조용히 죽는다.**
  `CancelledError` 는 `except Exception` 을 안 타 eof 미전송(connector.py:442-464).
  재연결 후 클라이언트는 살아있다고 착각. **터미널 재접속 스토리 전무.**
- **자원 상한은 UI 토스트가 아니라 서버측이 진짜.** `_ACTIVE` 에 전역 PTY 상한
  없음 + 업데이트=restart=`shutdown_all` 전멸(webterm.py:183). **v0.6.6 "세션 많은
  PC 사망" 사고 구역**으로 유도 → 서버측 PTY 상한 필수. [[006-update-healthcheck-incident]]

### 9-2. 확정 결정 (교차검증 후, §3 Decision 1 대체)
| 결정 | 최종 | 사유 |
|---|---|---|
| **스위칭 메커니즘** | **단일 xterm 재접속**(전환 시 대상 세션으로 1개 WS 재지향, 서버 detach+tail 리플레이 재사용) | 서버 설계에 정합, 실패모드 ②③⑥⑩⑪ 회피. 보유 xterm→Phase 2 |
| 연결 모델 | 전경 1개 라이브 WS(유지), **릴레이 rid stop 프레임 신규** | close no-op 갭 메움 |
| 탭 닫기 | detach vs 세션종료 선택(유지) + **stop 경로에 2FA 게이트 추가** | start 는 OTP, stop 은 미적용(connector.py 비대칭) |

### 9-3. Phase 1 필수 작업 (교정판 — §7 Phase 1 대체)
1. 전역 `_term` → **탭별 상태 dict**. 구조 리팩터 먼저(1탭=기존 동작 무변경), 그 뒤 멀티탭(Beck).
2. **단일 xterm 재접속** 스위칭 + 탭바 UI(데스크톱 탭/모바일 칩, 피커 재사용, × 닫기).
3. **릴레이 rid stop 프레임**(client→connector→해당 rid 로컬 WS close). 로컬 모드는 실 WS close.
4. **터미널 재접속**: 릴레이 재연결·`visibilitychange` 시 전경 탭 라이브 재프로브+재접속
   (+ `_pipe_terminal` 이 `CancelledError` 에도 eof 보내도록 수정 검토).
5. **서버측 PTY 소프트 상한**(webterm/`_ACTIVE`) — 진짜 상한. UI 경고는 보조.
6. 탭 닫기 detach/종료 선택 + **stop 엔드포인트 2FA 게이트**.
7. dedupe: `session_id` **및 `fork_id`**(포크 탭 정체성).
8. `CURRENT_TERM_SID` **단수→집합**(멀티탭 알림 선점/오억제 방지).
9. localStorage 복원: **신선한 세션목록 fetch → `live_terminal` 로 stale 판정**,
   삭제/이사된 sid(404) 처리, 전경만 attach(다른 기기 화면 탈취 인지).
10. 회귀 가드: 1탭=기존 동작, jsonl 무수정, PTY persist / 로컬·릴레이 양쪽 + node --check + 브라우저.

## 12. v0.8.0 — 탭 즉시 전환: 탭별 xterm 보유 + 화면 커서 델타 리플레이 (2026-09-11)

§9-2 에서 Phase 2 로 미뤘던 "보유 xterm" 을, 외부 보이스가 지적한 실패모드(서버가 재접속마다
tail 을 항상 리플레이 → 이중 렌더/공백)를 **"리플레이 억제 플래그" 대신 화면 커서**로 풀어 도입.
- **서버(webterm)**: 출력 스트림에 누적 오프셋(`total_len`, 링버퍼 시작 `base_off`). 화면마다
  `screen_id` 를 두고 서버가 *그 화면에 실제로 보낸* 오프셋을 기억(`screens`, reader 전송 성공 시
  전진). 재접속 시 `tail_since(cursor)` 로 **못 본 델타만**(배너 없음, 빈 델타면 무전송). 커서가
  없으면(첫 접속·구버전 클라) 기존 tail+배너, 버퍼를 넘겼으면 tail+"생략" 안내. 클라는 바이트를
  세지 않는다(문자 단위 불일치 회피). `/ws/terminal?screen=`, connector 가 `screen` 전달.
- **PWA**: `termView` 가 wrap 안에 탭별 host(xterm/iframe)를 절대배치로 보유, 전경만 `.on`.
  전환 = 이전 tc 닫기(stream_close, 서버 커서 유지) → 대상 표시·fit → `screen` 으로 tc. 라이브
  WS 는 여전히 전경 1개. 로컬은 탭별 iframe(항상 붙어 있음). screenId 는 페이지 수명 동안만.
- **실측으로 잡은 함정 2건**: ① 새 스폰 판정에 `SESSIONS.live_terminal` 을 쓰면 20초 폴링 stale
  로 살아있는 탭까지 비워 델타가 무너짐 → 복원 시점 `dead`(`wasDead`) 또는 서버 '세션 종료'
  텍스트(`t.ended`)만 사용. ② 세션 종료 시 서버 eof 가 먼저 와 `tc=null` 만 하면 `conn.streams`
  에 핸들러가 남음 → eof 에서도 `close()`.
- **검증**: 단위 8건(test_webterm_delta). relay e2e 는 **격리 Host**(`SESSION_MANAGER_CLAUDE_HOME`
  + A/B jsonl 복사 + CP 익명 자격증명으로 새 room, 프로덕션 무영향)에서: 왕복·재연결 내내
  screenId 불변·배너 0·마커 중복 0, 배경 답변이 복귀 시 델타로만 덧붙음, 정리 후 스트림 0.
  교훈: 릴레이 앱은 작업 트리를 라이브 서빙하지만 **Host 는 설치본**이라 서버 변경 e2e 는
  격리 Host 가 필수(설치본 상대로 돌리면 델타가 없는 게 당연).
- 미검증: 버퍼 초과 폴백(단위테스트만), 로컬 모드 e2e, 모바일 실기기 육안.
- **다중 기기 "세션당 화면 1개" 탈취전**: 폰이 세션 A 열면 데스크톱 A 화면이 밀림
  (webterm.py:407). dedupe 는 브라우저 내부라 못 막음. "화면 소유권 인계 UX"는 별도 과제.
- **업데이트가 워킹셋 전멸**: 업데이트 잦으면 복원은 거의 stale. 세션 jsonl 은 남으니
  재개는 되지만 라이브 프로세스는 사라짐 — 복원 UI 가 이를 정직하게 표시해야.

## 13. 탭 배지 상태 색 + 이벤트 툴팁 (v0.8.3 PWA, 2026-09-12)

**목표**: 배경 탭의 `●`(새 출력 있음)만으로는 "지금 뭘 하는 중인지"를 모른다. 목록이 이미 쓰는
훅 상태 뱃지(`sessionBadge`: 파랑 작업 중·주황 권한/입력 대기·초록 완료, 신선도 게이트 포함)를
탭 칩에도 같은 판정·같은 색으로 보여 학습 비용 0. 서버 변경 0.

**설계**
- 상태 = 칩 `::after` 밑줄 3px(세션 식별색 `.ldot` 과 분리). 진행형 상태는 `stblink` 깜빡임.
  탭 칩만 아래 여백 +2px(범례 칩과 규칙 공유하므로 `.term-tabs` 한정). 중지 탭은 상태 없음.
- 데이터 = 목록의 최신 `SESSIONS` 객체(`t.s` 는 switchTab 이 갱신하므로 표시용으로만 조회).
  20초 목록 폴링·loadList 뒤 term-mode 면 `renderTabBarSoon()`(300ms 코얼레싱 — 배지 이벤트마다
  스트립을 갈아엎지 않게). 활성 칩 `scrollIntoView` 는 활성 키가 바뀐 렌더에서만(`strip._sel`) —
  주기 재렌더가 사용자가 넘겨 둔 스트립 스크롤을 되돌리지 않게.
- 툴팁 = `상태: …` + 배경 탭 `● 새 출력 N건 · 최근: <종류> (<상대시각>)`. 종류는 모니터 이벤트의
  role/tools/tool_results 로: 도구 실행(이름 3개까지)/응답/도구 결과/프롬프트 입력. `tabBadge._on` 이
  `t.actN/t.last` 누적, 전환 시 소거. 모바일은 title 툴팁이 없으므로 색 밑줄이 전부.
- 즉시성의 한계: 상태는 훅 → Host → 20초 폴링. 배경 탭의 모니터 이벤트는 즉시 오지만 그것으로
  상태를 "추정"하지 않는다(목록과 다른 판정이 생기면 혼란). 필요해지면 Phase 2: 훅 상태를 모니터
  스트림에 실어 즉시 갱신.

**검증**: 릴레이 앱(작업트리 라이브)에서 실제 훅 데이터로 JS 구동 — thinking 세션 파랑 깜빡임,
합성 이벤트로 툴팁 건수·종류, 메모리 패치로 주황/초록, 배지 구독은 뷰 미마운트 시 생성 안 됨,
콘솔 오류 0. 미검증: 실제 터미널 탭 마운트 상태의 주기 재렌더, 모바일 실기기 육안.
