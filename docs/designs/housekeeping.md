# 정기 작업(housekeeping) — 쉬는 세션 정리 · 모델 목록 갱신 (2026-10-12 사장님 요청, Host 0.20.0)

> "세션이 너무 많이 열려 있으면 메모리가 부족하다. 4시간 이상 아무 작업 없이 열려만 있는 세션은 끄자. 끄기와 다른 세션의
> 살리기가 겹칠 수 있으니 관리 프로세스에서 큐잉. 모델 목록 갱신 같은 정기 처리도 정리해서."

실측(2026-10-12): claude 프로세스 12개 × 약 385MB = 4.6GB, PC 31.8GB 중 여유 4.5GB.

## 구조
- **작업 줄 하나**: Host 안 스레드 1개 + 큐(`session_manager/housekeeping.py`). 때가 된 작업과 「지금 실행」이 같은 줄에 서서 하나씩 돈다. 기동 +5분부터(업데이트 헬스체크 창 회피).
- **세션 수명 잠금**: `webterm.session_lock(sid)` — 터미널 띄우기(start_terminal·화면 열기)·끄기(stop_terminal)·정리가 같은 세션에서 한 줄로. 정리는 `webterm.stop_if` 로 **잠금 안에서 조건을 다시 확인**한 뒤에만 끈다 → 관리 세션이 워커를 깨우는 순간이나 누가 화면을 연 순간과 겹쳐도 끄지 않는다. 별도 관리 프로세스를 두지 않은 이유: PTY 는 이미 Host(→브로커) 한 곳에서만 띄우고 끄므로 Host 안의 잠금이 곧 큐다.
- 상태: `data_dir/housekeeping.json`(켜짐·기준 시간·마지막 실행/결과). 화면: 설정 → 데이터 · 사용량 → 🧹 정기 작업. 원격 변경·「지금 정리」는 2FA.

## 쉬는 세션 정리(15분마다, 기본 4시간)
대상: ClewPath 가 띄운 터미널(PTY)만 — 터미널에서 직접 띄운 claude 는 손대지 않는다. 끄는 조건(모두):
- 마지막 활동(jsonl 기록·훅 이벤트·키 입력·화면 열고 닫기·이 Host 가 붙인 시각) 뒤 기준 시간 경과 — Host 업데이트 직후엔 시계가 새로 시작(보수적)
- 화면이 붙어 있지 않음 · 권한 승인 대기 아님 · 백그라운드 쉘·모니터 0개 · 📌 항상 켜 두기 아님(세션 상세 → 더 보기)
끈 뒤: 감사 기록(`idle_stop`) + 폰 알림 한 번(「쉬던 세션 N개를 껐습니다」). 대화 기록은 그대로라 다시 열면 이어진다. 워커는 관리 세션이 다음 일감 때 다시 깨운다(clewpath-workers 1·2단계).

## 모델 목록 갱신(하루마다)
claude CLI 엔 모델 열거가 없고 구독(OAuth) 계정이라 Models API 도 못 쓴다(자격 파일 읽기 금지). → 운영측(CP) 목록 + **이 PC 세션들이 실제로 쓴 모델**(assistant message.model) 합본을 `data_dir/models.json` 에 두고 `/api/models` 가 우선 쓴다. 새로 쓰인 모델이 위로. 내장 기본 목록도 Opus 5.5 등으로 갱신.
