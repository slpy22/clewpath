# 정기 작업(housekeeping) — 쉬는 세션 정리 · 모델 목록 갱신 (2026-10-12 사장님 요청, Host 0.20.0)

> "세션이 너무 많이 열려 있으면 메모리가 부족하다. 4시간 이상 아무 작업 없이 열려만 있는 세션은 끄자. 끄기와 다른 세션의
> 살리기가 겹칠 수 있으니 관리 프로세스에서 큐잉. 모델 목록 갱신 같은 정기 처리도 정리해서."

실측(2026-10-12): claude 프로세스 12개 × 약 385MB = 4.6GB, PC 31.8GB 중 여유 4.5GB.

## 구조
- **작업 줄 하나**: Host 안 스레드 1개 + 큐(`session_manager/housekeeping.py`). 때가 된 작업과 「지금 실행」이 같은 줄에 서서 하나씩 돈다. 기동 +5분부터(업데이트 헬스체크 창 회피).
- **세션 수명 잠금**: `webterm.session_lock(sid)` — 터미널 띄우기(start_terminal·화면 열기)·끄기(stop_terminal)·정리가 같은 세션에서 한 줄로. 정리는 `webterm.stop_if` 로 **잠금 안에서 조건을 다시 확인**한 뒤에만 끈다 → 관리 세션이 워커를 깨우는 순간이나 누가 화면을 연 순간과 겹쳐도 끄지 않는다. 별도 관리 프로세스를 두지 않은 이유: PTY 는 이미 Host(→브로커) 한 곳에서만 띄우고 끄므로 Host 안의 잠금이 곧 큐다.
- 상태: `data_dir/housekeeping.json`(켜짐·기준 시간·마지막 실행/결과). 화면: 설정 → 데이터 · 사용량 → 🧹 정기 작업. 원격 변경·「지금 정리」는 2FA.

## 쉬는 세션 정리(15분마다, 기본 4시간)
대상: ClewPath 가 띄운 터미널(PTY)만 — 터미널에서 직접 띄운 claude 는 손대지 않는다. 끄는 조건(모두):
- 마지막 활동(jsonl **대화 줄**(user·assistant·작업 알림) 시각·훅 이벤트·키 입력·화면 연 시각·터미널을 띄운 시각) 뒤 기준 시간 경과 — 0.20.3: Host 업데이트로 다시 붙여도 브로커가 띄운 시각을 이어 쓴다(전엔 업데이트마다 시계가 0 부터라 정리가 계속 밀림)
  - 0.20.2: jsonl **파일 수정 시각은 쓰지 않는다** — claude 가 쉬는 동안에도 끝에 시각 없는 메타 줄(last-prompt·mode·atis-latch·artifact-autoreact-ledger 등)을 다시 써서 늘 '방금' 이 됐다(밤새 4개가 안 꺼진 원인, 2026-10-13 실측). 자동 압축 요약(isCompactSummary)·system 줄도 활동이 아니다.
  - 0.20.2: **화면이 붙어 있는 것만으로는 지키지 않는다**(밤새 열어 둔 탭). 보는 중 claude 가 일하면 대화 줄이, 치면 입력 시각이 갱신된다.
- 권한 승인 대기 아님 · 백그라운드 쉘·모니터 0개 · 📌 항상 켜 두기 아님(세션 상세 → 더 보기)
끈 뒤: 감사 기록(`idle_stop`) + 폰 알림 한 번(「쉬던 세션 N개를 껐습니다」). 대화 기록은 그대로라 다시 열면 이어진다. 워커는 관리 세션이 다음 일감 때 다시 깨운다(clewpath-workers 1·2단계).

## 모델 목록 갱신(하루마다, Host 0.20.1)
1. **claude `/model` 화면 읽기**(modelprobe.py, 2026-10-12 사장님 승인): claude 가 업데이트됐거나 7일 지났을 때만, 숨은 터미널에
   `claude --session-id <새 id>` 를 띄워 `/model` → 아래 화살표로 끝까지 → Esc. 화면은 작은 VT 해석기(Screen)로 그려 읽는다
   (claude 는 바뀐 칸만 다시 그려서 문자열로는 스크롤 아래 모델을 놓친다). 이 계정이 고를 수 있는 목록 그대로(실측 12개).
   안전: Enter 는 입력칸에 `/model` 이 보일 때 1번뿐 · 고르기 화면에선 ↓·Esc 만(기본 모델 불변 실측) · 신뢰 질문 등 낯선 화면이면
   아무것도 입력 않고 끝 · 신뢰 폴더 중 .mcp.json·프로젝트 훅 없는 곳 · 남는 빈 세션 기록은 id 를 적어 목록에서 숨김.
   실패하면 이전 목록 + ⚠.
   **0.33.11(2026-10-29 사장님)**: 10-28 17:16 한 번 `start_timeout`(30초 안에 시작 화면 없음, 다시 해 보면 5.5초)이 났는데
   실패에도 claude 버전을 적어 11-04(7일 뒤)까지 다시 읽지 않았다 → ① 실패는 `at`·`version` 을 바꾸지 않아 다음 주기(24시간)에 다시
   ② 실패하면 닫기 전 화면 꼬리 12줄(이메일 가림)을 `housekeeping.json` 의 `probe.last_screen` 에(화면에는 안 냄) ③ 「지금 실행」은 강제로
   다시 읽음(`kick(force=True)`, 작업 줄이 때가 돼 세운 것은 평소대로) ④ 시작 화면 기다림 30초 → 60초.
   **0.33.12(같은 날) 진짜 원인**: 0.33.11 의 실패 화면 꼬리가 바로 보여 줬다 — claude 2.1.312 는 입력칸을 `❯` 가 아니라 `> ` 로
   그린다(`> Try "…"`, 아래 `⏵⏵ auto mode on`). `❯` 만 찾아 매번 start_timeout 이었다(일시 지연 아님). 줄 맨 앞의 `❯`·`>` 둘 다
   입력칸으로 본다(`_PROMPT_RE`·`_ECHO_RE`). 실기: 진짜 claude 2.1.312 로 18.9초·12개 읽음.

## 지워질 세션 예고(하루마다, Host 0.20.6 · 2026-10-13 사장님 — E:\001_KIS 세션 3개 실종)
claude 는 시작할 때 **마지막 수정 뒤 `cleanupPeriodDays`(~/.claude/settings.json, 기본 30일)가 지난 대화 기록을 지운다**. ClewPath 휴지통을 거치지 않아 되살릴 수 없다.
- `retention.py`: 설정을 **읽기만** 해(값을 바꾸지 않음, 불가침 원칙 1) 세션마다 `cleanup_at = mtime + 보관 일수` 를 v1 목록에 싣는다. 0 이하면 예고 안 함.
- 화면: 7일 안 = 목록 ⏳ 칩·🔔 「곧 지워질 세션」 묶음·상세 경고(재개해서 한 번 주고받으면 기한 연장 · 내보내기로 보관). 3일 안 = 🔔 숫자에 포함·빨강.
- 정기 작업 `cleanup_watch`(하루): 3일 안에 지워질 세션을 폰으로 알림 — 세션마다 7일에 한 번. 자동 실행 기록·모델 읽기용 빈 기록은 제외.
- 실제 삭제는 기한 뒤 claude 가 처음 뜰 때라 '쯤' 이다.
