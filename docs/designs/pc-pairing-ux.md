## 용어
- **PC / Host**: 사용자 PC 의 ClewPath 서비스(127.0.0.1:5100). **로컬 웹** = 그 PC 브라우저의 화면.
- **기기**: PC 에 접속을 허락받은 폰/브라우저/앱. Host `devices` 등록부 1행(이름·기기 토큰 해시·cpub·revoked·last_seen).
- **cpub / client credential**: 기기당 CP 가 발급한 자격(public_id+secret). 폰은 이걸 단기 JWT 로 바꿔 릴레이에 붙는다. 폐기되면 **다음 JWT 발급이 거부**된다(이미 발급된 JWT·열린 연결은 별개 → 커넥터가 스트림을 끊어야 한다, T1).
- **기기 토큰(dev)**: Host 등록부가 검증하는 자격. 커넥터가 요청마다 대조(`token_version`).
- **릴레이 / 커넥터 / cid**: 릴레이는 room 별 폰(client)↔Host(agent=커넥터) WS 중계. 폰 연결마다 **cid**. 커넥터→릴레이 프레임은 `cid` 로 특정 폰에 전달(relay.py:494, 검증됨).
- **room**: Host 1대 = room 1개.

## Vision — 문제의 재정의
"추가/삭제/로그아웃 UI 정리" 가 아니라 **한 관계(PC↔기기 페어링)가 세 저장소(Host devices / 브라우저 sm_pcs / CP cpub)에 흩어져 서로를 모른다** 는 모델 문제. 그리고 리뷰 중 발견: **그 관계의 권한 경계 자체가 코드에서 새고 있다**(T1). 순서는 ① 경계를 막고 ② 관계를 하나로 ③ UI 는 그 두 관점.

10x(코드 페어링)·C(CP 정본화)는 TODOS. 접근안 B 채택(D1).

## 폰 PC 항목 상태기계
```
paired ──(이 PC 페어링 해제)──▶ local_removed ──(revoke-self 200/401)──▶ (삭제)   ※ 실패: revoke_pending(큐, 재시도)
paired ──(notice device_removed | CP 401 | Host auth_invalid)──▶ removed_by_pc(⛔) ──[다시 페어링: 새 QR]──▶ paired
paired ──(notice device_reissued)──▶ reissued(배지, 항목 유지) ──[새 QR]──▶ paired
불가능: removed_by_pc 에서 자동 재접속(재접속 대상 제외) / 큐 항목이 초기화로 삭제(키 보존)
```

## 검증 기준 (6-1)
하네스(node)·pytest·007 pytest + **격리 Host(5199)+CP 새 room e2e**: 페어링(이름 자동) → 폰 해제(온라인/오프라인 큐) → PC 📵 → PC 삭제 → 폰 ⛔(온라인 notice / 오프라인 CP 401) → 재발급 → 배지·새 QR 이어짐 → T1 프록시 403·스트림 해체. 실폰은 사장님.

## 제약(불변)
- 기기 등록·삭제·재발급·이름 변경은 PC 로컬에서만 — **T1 로 실제로 강제**. 폰은 자기 자격 폐기·자기 이름 보고만.
- 비밀은 fragment(#), E2EE 키는 로컬만, CP 신규 저장 없음(큐 재시도용 secret 은 폰 로컬 `sm_revoke_queue` 에만).
- 릴레이: 폰↔커넥터 프레임 형식 무변경(`notice`·`bye_device` 는 기존 라우팅을 타는 새 type — 구버전은 무시). 릴레이 코드 변경 없음(E-1 연기로).
- claude 파일 무접촉.
