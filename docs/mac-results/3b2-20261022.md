## 이슈

### 이슈 A. 옛 화면 `/legacy`의 API 주소가 `/legacy/api/…`가 되어 404가 난다 → 재개 창이 틀리게 나온다

- **어디서**
  - `session_manager/static/index.html:158`의 `const BASE=location.pathname.replace(/\/+$/,"");`
  - `/legacy`로 열면 `BASE = "/legacy"`가 되어, API를 모두 `/legacy/api/…`로 부른다.
- **Host 기록** (`host.log`, 필요한 줄만)
  ```
  "GET /legacy HTTP/1.1" 200 OK
  "GET /legacy/api/owner/diagnostics HTTP/1.1" 404 Not Found
  "GET /legacy/api/sessions HTTP/1.1" 404 Not Found
  "GET /legacy/api/sessions/8646017e-…/resume-command HTTP/1.1" 404 Not Found
  ```
- **결과**
  - 재개 창은 404 본문(`{"detail":"Not Found"}`)을 받는다. 거기에는 `r.error`가 없어서 창이 그대로 열린다.
  - `r.cwd`가 비어 있어 명령이 `claude --resume 8646017e-… --dangerously-skip-permissions`로 나온다 (`cd` 없음).
  - `r.can_launch`도 없어서 `!== false` 조건이 참이 되고, **'새 cmd 창에서 실행' 단추가 보인다** (사장님 확인).
- **맥 수정 자체는 맞다**
  - 같은 Host의 `GET /api/sessions/8646017e-…/resume-command`는 `cwd`, `shell:"sh"`, `can_launch:false`를 준다.
  - 화면 코드(`index.html:458·469`)는 이 값으로 `cd '…'`와 단추 숨김을 처리한다.
  - `/legacy` 주소 버그는 맥 전용이 아니다 (짐작: Windows에서도 `/legacy`로 열면 같다).
- **참고**: 기본 화면(`/`, 통일 PWA)의 '▶ 재개'는 명령 창 없이 바로 웹 터미널로 이어진다. 1회차에 사장님이 본 "재개가 되는 것"도 이 길이었다.
- **제안**: 옛 화면도 `{{BASE}}`를 치환해 쓴다. `_render_html`이 이미 치환한다.
