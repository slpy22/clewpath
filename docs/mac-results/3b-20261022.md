## ★ 이슈 (Windows 측 수리 거리)

### 이슈 1. 시험이 이 맥의 실제 파이썬 인터프리터에서 실행 권한을 뺐다 (M2 1회차)

- **어디서**
  - `tests/test_update_runner_sh.py:531-541`. `Upd` 정리 단계가 `os.walk(self.base)`로 돌며 모든 파일에 `os.chmod(…, 0o644)`를 건다.
  - 그 안의 `.venv/bin/python`은 `sys.executable -m venv --without-pip`로 만든 **심볼릭 링크**이고, 맥(pyenv)에서는 `~/.pyenv/versions/3.11.9/bin/python3.11`을 가리킨다.
  - `os.chmod`는 링크를 따라가므로 **진짜 인터프리터가 0644가 됐다** (ctime 08:54:42).
- **결과**
  - 그 뒤 시험 거의 전부가 `PermissionError: [Errno 13] Permission denied: '…/.venv/bin/python'` 에러로 끝났다.
  - 1회차 집계: 97 failed / 85 errors.
  - 이 맥에서 pyenv python 3.11 전체를 못 쓰게 됐다. `uv run`도 `Failed to query Python interpreter`로 실패했다.
- **리눅스 컨테이너에서 안 보인 이유(짐작)**: 그쪽 인터프리터는 root 소유라 chmod가 EPERM으로 조용히 실패한다. 맥(pyenv)이나 사용자 소유 파이썬에서만 드러난다.
- **맥에서 한 조치**
  - 권한을 `chmod 755`로 되돌렸다.
  - 2회차는 인터프리터에 `chflags uchg`를 걸어 chmod만 막고 돌렸고, 끝난 뒤 풀었다. 저장소 코드는 바꾸지 않았다.
- **고칠 곳 제안**: 정리 루프에서 링크를 건너뛴다.
  ```python
  p = os.path.join(d, n)
  if os.path.islink(p):
      continue
  ```

### 이슈 2. 시험 중에 실제 claude가 실제 `~/.claude`에 `/model` 세션을 남겼다

- **증거**
  - `~/.claude/projects/-Volumes-Works-Projects-clewpath/`에 1227바이트짜리 세션 3개가 생겼다.
    - `b99bce47…` (08:54:10)
    - `3f20eca5…` (08:54:24)
    - `dd5ead77…` (09:01:39)
  - 내용은 `/model` → "Kept model as `Opus 5.5`" 뿐이다.
  - `~/.claude/history.jsonl`에도 같은 시각에 `/model` 세 줄이 있다.
  - 시각은 M2 1회차(08:48–08:54)와 2회차(08:56–09:05) 사이에 들어 있다. 그 시간에 사람은 claude를 따로 띄우지 않았다.
- **모양**: ClewPath 「모델 목록 갱신」(modelprobe)과 같다. 신뢰 폴더에서 claude를 띄우고, `/model`을 연 뒤 Esc로 닫는다.
- **짐작 원인**
  - `modelprobe.pick_cwd()`가 `Path.home() / ".claude.json"`을 읽는다.
  - `probe()`는 `CLAUDE*`·`SM_*` 환경변수만 빼고 실제 HOME으로 claude를 띄운다.
  - 그래서 시험이 `SESSION_MANAGER_CLAUDE_HOME`만 가짜로 바꿔 둔 상태에서 정기 작업이 실제로 돌면, **진짜 claude가 진짜 `~/.claude`에 쓴다.**
  - 어느 시험이 그 작업을 돌렸는지는 특정하지 못했다.
  - 이 맥에는 PATH에 `claude`가 있어서 드러났다.
- **부작용**
  - 숨김 목록(`probe_sessions`)은 시험의 데이터 폴더에 적혔다. 그래서 실제 Host 목록에는 이 세 세션이 그대로 보인다.
  - 세 세션은 지우지 않고 그대로 두었다 (`~/.claude` 무접촉).
- **제안**
  - 시험 전체에서 modelprobe의 `probe`·`pick_cwd`를 막는 conftest 가드를 둔다.
  - 또는 `pick_cwd`·`probe`가 ClewPath의 claude home 설정을 따르게 한다.

### 이슈 3. 맥에서 사용자에게 보이는 이름이 "sh"와 "python3.11"이다

- **백그라운드 항목 알림**: `App Background Activity, "sh" can run in the background. You can manage background activity in Login Items & Extensions`
  - 시스템 설정 → 로그인 항목에도 **"sh"**로 보인다 (사장님 확인).
  - `sfltool dumpbtm` 기록: `Name: sh`, `Type: legacy agent`, `Identifier: 8.com.clewpath.host`, `Parent Identifier: Unknown Developer`.
- **웹 터미널에서 claude를 처음 열 때** "python3.11이 …에 접근하려고 합니다" 창이 항목마다 따로 떴다. 사장님이 모두 허락했다.
  - 떠 있던 항목: **데스크탑, 문서, 사진, iCloud, OneDrive, Google Drive**
  - 이유: launchd → Host(python) → 브로커(python) → claude 순서라서, macOS(TCC)가 이 접근의 책임 앱을 python3.11로 본다.
  - uv 관리 파이썬은 `Signature=adhoc`, `Identifier=-`라 이름만 python3.11로 나온다.
  - 터미널 앱에서 claude를 쓸 때는 책임 앱이 터미널 앱이라 이 창이 안 뜬다.
- **재설치 뒤**: 파이썬을 지우지 않았으므로 권한 창이 다시 뜨지 않았다. 파이썬이 바뀌는 업데이트(경로나 해시 변경)라면 다시 뜰 수 있다 (짐작).
- **사장님 의견**: "이런 거 안 뜨고 설치 시에 허락돼 버리면 좋겠다."
  - macOS는 프로그램이 스스로 권한을 줄 수 없다. 그래서 다음 같은 방향을 검토할 만하다.
    1. Host·브로커를 서명된 `ClewPath.app` 꾸러미 안에서 띄운다. 그러면 표시 이름이 ClewPath가 되고, 권한이 업데이트 뒤에도 유지된다.
    2. 설치 마지막에 '전체 디스크 접근' 설정 화면을 열어 주고 안내한다.
- **제거 뒤**: plist는 지워졌지만 `sfltool dumpbtm`에 이 항목("sh")은 그대로 남아 있었다.

   - 1회차 로그아웃(10:08) 때 그런 Host(pid 93460)가 죽지 않았고, 로그인 때 launchd 작업은 exit 0으로 그냥 끝났다.

   - 같은 이유로, launchd 밖에서 뜬 Host가 죽으면 KeepAlive(30초)가 아니라 5분 확인이 받는다 (M3-4-1의 281초).
   - 그 사이 사장님의 2회차 로그아웃이 실제로 안 된 일이 있었다. 그때 `stop`(10:10:26) 뒤 5분 확인이 10:13:59에 Host를 띄웠다(+213초). 5분 확인을 한 번 더 확인한 셈이다.
4. **`stop --hold` 상태 표시**: `state=maintenance`, `maintenance=1`로 나온다. 지시서는 "stopped 인지"라고 적었다. 동작은 맞다(안 뜸).
5. **5분 확인의 최악 시간**: StartInterval 300초에 기동 시간이 더해져 3단계는 301초 걸렸다. "5분 안에"는 경계에 걸린다.
6. **브로커**
   - 설치 직후에는 `broker_pid=` 비어 있음, `broker_alive=0`이다. 처음 터미널을 열 때(10:26:10) Host의 자식으로 떴다(PPID = Host).
   - Host를 `kill -9` 하면 PPID 1로 넘어가 살아남았고, 새 Host가 다시 잡았다.
   - 재설치 때는 설치 중에 바로 떴다(pid 30262).
   - 웹 터미널의 claude 명령줄: `claude --resume <id> --dangerously-skip-permissions`.
7. **데이터 폴더 권한**: 재설치 때 "group·other 권한을 뺀 항목 24개"가 나왔다. Host가 도는 동안 umask 022로 0644 파일을 만든다. 폴더 자체는 0700이다.
8. **M0의 pwd**
   - Claude Code 셸(zsh)에서 `cd /applications && pwd -P`를 하면 `/Applications`가 나온다. zsh의 `pwd -P`가 물리 경로를 준다.
   - `/bin/sh -c` 안에서는 지시서의 기대대로 `/applications`, 그리고 `/bin/pwd -P`는 `/Applications`다.
9. **M5 확인 질문**: `/dev/tty`로 묻는다. 처음에 `script`로 `y`를 넣다가 입력 순서가 꼬여 `^D` → "취소했습니다 — 아무것도 바꾸지 않았습니다"(rc=1)가 됐다. 안전하게 취소됐다. `expect`로 다시 하니 정상이었다.
10. **설치 [6/6] 안내**: "폰에서 쓰려면: 로컬 웹 오른쪽 위 [📱]"라고 나온다. 지시서 M4-4는 🖧 → ＋ 새 PC 추가라고 한다. 같은 흐름이라면 무시해도 된다.
