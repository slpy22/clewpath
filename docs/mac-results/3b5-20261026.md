## T4 3a e2e 시나리오 맥에서 (가짜 홈, 저장소 밖 래퍼)

### 방법

이 맥에는 docker·colima·podman이 없다. 드라이버(`tests/posix_e2e/e2e_driver.py`)는 컨테이너 밖에서는 거부하고(`CLEWPATH_E2E_CONTAINER=1`·`/.dockerenv`·리눅스), 프로세스를 `/proc`로 본다. 그래서 드라이버를 **그대로 불러 쓰는 래퍼**를 저장소 밖(`/tmp/clewpath-3b5/mac_e2e.py`)에 만들었다. 바꾼 것은 이것뿐이다.

| 바꾼 것 | 리눅스 컨테이너 | 맥 래퍼 |
|---|---|---|
| 가드 | 컨테이너 표식 | 맥 + `HOME`이 가짜 홈(`/private/tmp/clewpath-3b5/e2e-home`) + PATH 맨 앞의 막아 둔 `launchctl` + PATH에 claude 없음 + 포트 빔 |
| 설치 위치 | `~/.local/share/clewpath` | `~/Library/Application Support/ClewPath`(맥 기본, 가짜 홈 아래) |
| 포트 | 5100 | **5400**(진짜 Host가 5100). 확인은 모두 `DEFAULT_PORT`를 써서 ⑧은 5400 → 5401로 본다 |
| 설치 인자 | `--cp-url … --allow-http --relay-url … --app-url …` | 같고 + `--port 5400 --no-autostart`(get.sh·install.sh 재실행·다시 설치 모두) |
| 프로세스 | `/proc/<pid>/cmdline·stat·environ` | psutil(같은 사용자만) |
| TIME_WAIT | `/proc/net/tcp` | `netstat -an -p tcp` |
| umask | `/proc/<pid>/status` | 읽을 길이 없음(빈 값) |
| 재료 | `build_fixtures.py` | 같은 도구, `--uv-target aarch64-apple-darwin --no-pwsh`(uv 0.12.1 맥용, install.sh 고정 해시와 대조). `index.json`의 uv 경로만 맥 경로로 |

진짜 설치본을 지키는 장치:
- 실행은 `env -i`로 깨끗한 환경에서 했다. 남긴 것은 `HOME`(가짜)·`PATH`·`USER`·`LANG`·`TMPDIR`뿐이다.
- `install.sh`는 `--no-autostart`가 없으면 가짜 홈에서도 `launchctl bootout gui/<uid>/com.clewpath.host`로 **진짜 작업을 내린다**(1153행, 이름이 하나뿐). 그래서 인자에 `--no-autostart`를 넣고, PATH 맨 앞에 받은 것을 적고 실패로 답하는 `launchctl`도 두었다. 결과적으로 한 번도 불리지 않았다.
- 제거의 「남은 것 쓸기」(`uninstall.sh` `sweep`)와 러너의 실패 Host 정리(`update_runner.sh` `host_pids`·`is_our_host`)는 `$ROOT/.venv/bin/`이 든 프로세스만 대상으로 한다. 가짜 홈 설치본의 것만 닿는다는 것을 코드로 확인했다.
- 앞뒤 비교: 진짜 Host `pid 98725 alive=True → pid 98725 alive=True`, 진짜 등록 파일 해시 `2da77658f4327342 → 2da77658f4327342`, 남은 가짜 홈 프로세스 `[]`.
